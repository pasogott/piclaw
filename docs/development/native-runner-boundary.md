# Native direct-runner boundary

`AgentPool.runAgent()` is a legacy compatibility API. A pool constructed with a captured native session lookup, including an empty lookup, rejects this method before eviction protection, option getters, budget work, orchestration, session construction or model calls.

The result is `{ status: "error", result: null, error: "Native execution requires an admitted operation", failureCategory: "non_recoverable" }`. Caller-supplied budget IDs or provenance cannot turn a direct prompt into accepted native work. Non-native compatibility pools retain their existing runner behaviour.

Native execution must use its qualified accepted-source dispatch: ordinary input admission, scheduled dispatch with the exact lease/source proof, or the existing bound side-prompt contract. These ports have different authority and context requirements; a side prompt is not a generic substitute for unbound background work.

This guard is a prerequisite in #1670, **not completion of the caller migration**. Dream's transient context/model policy, granted add-on execution and non-web admission still need their admitted native ports and defining provider/replay tests. The remaining legacy web path belongs to #1674. Dream, add-on operations and non-web support are not retired by this guard. Their native direct calls already failed at legacy-session construction; they now fail without creating and completing a misleading budget-work row.

The polling caller also refuses native messages explicitly with `Native non-web message processing requires host input admission`. This happens before control/slash commands, command deduplication, timestamp commits or a call to `runAgent()`. The coordinator passes the captured pool mode to the polling loop, which checks this boundary before enqueueing any fetched batch or publishing its global timestamp. Checking only inside asynchronous per-chat work would still consume the polling cursor. Pending inputs and both per-chat/global cursors remain intact; no outbound success or fabricated user message is produced. Empty polling batches still return normally. Legacy non-native transports retain their existing execution path. This is the explicit unsupported native polling decision allowed by #1670, not retirement of non-web transport support or proof that Dream/granted operations are migrated.

Focused qualification covers the real native pool with independent pending ordinary, model-control and slash-command inputs: all records remain unchanged, no command/dedup/timestamp/runner/provider path runs and legacy factories stay unused. The directly affected non-native processing, poll-cancellation/partial-admission/shutdown and coordinator fixtures still pass.

Dream's deterministic failure refresh is also retained: a thrown agent outcome still refreshes authorised notes and the workspace index, then propagates the original exception without marking consolidation complete or retrying. A refresh/cleanup failure preserves both errors; revoked access blocks further data mutation while the held lock is released. Its lock lease is bound to the exclusively opened descriptor, device/inode and exact PID bytes; maintenance rechecks that identity after awaits. Creation writes through the descriptor. Cleanup and process exit retain replacement/aliased locks, and both the owned lease and stale-inspection descriptor stay open through their binding decisions to prevent inode reuse. Only `ESRCH` plus an unchanged regular-file snapshot permits stale reaping; malformed, aliased, unreadable or unknown-process locks remain held. FIFO/special-file checks cannot block inspection. The legacy PID-file format is unchanged. These focused host-flow tests do not establish that an admitted native Dream port exists.

Other focused qualification covers real default-factory/native-pool calls for bound, missing, Dream, add-on-operation and non-web-shaped identities; exact/empty captured lookup cases; untouched database/files and zero option/factory/provider calls; and one existing non-native compatibility run. No deployment, live-state cleanup or historical-data removal is implied.
